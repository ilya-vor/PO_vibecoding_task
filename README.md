# Semantic TextNavigator — проверка условий договора поставки

Один `index.html`: загружает TXT и сводит договоры в таблицу (номер, поставщик, сумма, срок
на дату проверки). У каждого значения основание: файл + цитата + переход к абзацу. Работает
локально, без сервера и API; внутри правила и regex, не LLM. ИИ применялся при разработке.

## Запуск

Открыть `index.html` в браузере → «Загрузить учебный пример» или перетащить `.txt` → при
необходимости поменять дату проверки (по умолчанию 10.03.2026).

**Установка и зависимости не нужны.** `python` 3 — только для опционального сервера:
`python -m http.server 8199` → `localhost:8199/index.html` (если блокируется `file://`).

Поставка: `index.html`, `documents/` (6), `test_files/` (15 сценариев), `README.md`.

## Ограничения

- Только TXT (UTF-8 / Windows-1251); PDF/DOCX/OCR — вне задания.
- Правила под формат документов задания; другая вёрстка — правка правил.
- Суммы без разделителей (`1250000`) — да; прописью и `1.380.000,00` — нет.
- Без явной строки «Статус» документ условия не меняет; данные никуда не отправляются.

## Архитектура и решения

`parseDoc` → `analyze` (сортировка соглашений по дате, источники полей, `unagreed`) →
`render*` + `openViewer`; `F1…F6` — копии `documents/` для демо.

1. **Правила вместо LLM** — детерминизм;
2. **Одно состояние `analyze`** — таблица и ответы не расходятся;
3. **Приоритет по подписанности и дате** — проект и письмо не меняют договор;

**100k документов:** парсинг в Web Worker/на бэкенде, индекс по номеру, виртуализация,
ленивая подгрузка текста. **Права:** дата проверки как контекст, фильтрация по ролям и
договорам, журнал доступа. **Дальше:** 1) неустойка/аванс/срок оплаты; 2) «было/стало» и
экспорт; 3) автотесты, PDF/DOCX.

## Записка для заказчика

**Пользователь:** специалист по закупкам, сверяет условия, не перечитывая документы.
**Вопросы:** какие ещё поля контролировать; форматы и разнородность вёрстки; конфликт
нескольких соглашений; уведомления о просрочке; кто ставит статус подписания.
**Допущения:** дата проверки вручную; сумма итоговая с НДС, аванс — её часть; лимит
бюджета не стоимость; связь по `STN-\d+`.
**Метрики:** точность извлечения суммы/срока на размеченном наборе; время до таблицы.

## Отчёт о вайбкодинге

**Инструмент:** pi coding agent + local llm/deepseek (код и правки), результат — один `index.html`. **Запросы:**
каркас «один файл, TXT, таблица, 4 вопроса, цитаты, без сервера и LLM»; устойчивый regex
суммы; нормализация ISO-даты и порядок аргументов `new Date()`.

**Ошибки ИИ и исправления:** «подписания» из «после подписания сторонами» принималось за
подпись → статус только из строки «Статус», `amendment_draft` не применяется;
`new Date(year, day-1, month)` давал `20270803` → `(year, month-1, day)`; `поставк\w*` не
совпадал с «поставки» → `поставк[а-я]*`; ответы были захардкожены → всё из `analyze()`;
сумма бралась из «стоимости доставки» → оценка кандидатов и «требуется проверка».
